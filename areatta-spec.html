01. コンセプト・解決課題

買い物中の「これ家にあったっけ？」、調理前の「早く使わないといけないのどれだっけ？」、献立を決めるときの「冷蔵庫の中身から何作れる？」——この3つのシーンを最小限の操作で解決する。

コアバリュー
冷蔵庫に食材を入れながら声で登録→ 期限が近い順に一覧表示 → 「使い切り」メニューをAIが提案する。この一連の流れだけをシンプルに実現する。

3つの使用シーン

A
🛒 スーパーで
「あの食材、まだ残ってたっけ？いつまで使えるんだっけ？」
→ スマホで一覧を見るだけ。検索不要、開いた瞬間に全部見える。
B
🧊 帰宅・買い物を冷蔵庫に入れながら
「牛乳500ml期限9月20日、卵6個期限9月25日」と読み上げるだけ。
→ AIが自動解析して構造化データとして保存する。
C
🍳 料理するとき
「今日何作ろう？期限が近いものから使いたい」
→ 「おまかせ献立」ボタンでAIがレシピを提案。

02. MVPスコープ

「なんでもできるアプリ」ではなく、3つのシーンを解決することに集中する。

✓ MVP IN

— スコープ外

03. 画面構成

ボトムナビゲーションで3画面を切り替える。シンプルに3タブのみ。

S1
冷蔵庫一覧（ホーム）
登録済み食材を消費期限の近い順に表示。グルーピング: 期限切れ / 今日 / 明日 / 今週 / それ以降。右上の「＋」ボタンで音声登録へ。「おまかせ献立」ボタンを常設。
期限別グループ スワイプで削除 タップで編集 残り日数バッジ
S2
音声登録
大きなマイクボタンを押して読み上げる → 認識テキストをリアルタイム表示 → Claude APIで解析 → 確認画面で修正可能 → 保存。連続登録モード対応（次々と読み上げられる）。
マイクボタン リアルタイム文字起こし 解析結果プレビュー 手動修正フィールド 連続登録

モード切替 リクエスト入力 レシピカード 使用食材ハイライト
S4
食材編集（モーダル）
S1からタップで開くモーダル。食材名・数量・消費期限・メモを編集可能。削除ボタンあり。
インラインモーダル 日付ピッカー 削除確認

04. ユーザーフロー

フロー A: 音声で食材を登録する

1
「登録」タブをタップ 大きなマイクボタンが表示された画面に遷移
2
マイクボタンをタップして話す 「牛乳500ml期限9月20日、卵6個期限25日」などと読み上げる。テキストがリアルタイムで画面に表示される。
3
「解析」ボタンをタップ Claude API (Haiku)に送信。パース結果として「食材カード」が並んで表示される。数秒で完了。
4
内容を確認・修正して「保存」 間違いがあればフィールドを直接編集。問題なければそのまま「保存」→ Supabaseに登録 → 一覧画面に戻る。

フロー B: 献立を提案してもらう

1
「献立」タブをタップ モード選択と「提案を出す」ボタンが表示される
2
モードを選ぶ 「早く使いたい順」→ そのままボタン押下。「食べたいもの優先」→ テキスト入力（例：「今日は煮物系が食べたい」）
3
「提案を出す」をタップ Claude API (Sonnet)に送信。3〜5品のレシピカードが返ってくる。各カードに食材・手順・調理時間を表示。

05. データモデル

Supabase テーブル設計

ingredients テーブル

カラム名 型 説明 例
id UUID PK、自動生成 gen_random_uuid()
name TEXT 食材名。NOT NULL 「牛乳」「鶏もも肉」
quantity TEXT 数量・単位。自由テキスト 「500ml」「2枚」「少し」
expiry_date DATE 消費期限。NULLは「不明」扱い 2026-09-25
category TEXT カテゴリ。enum候補: meat / dairy / vegetable / seasoning / other 「dairy」
note TEXT メモ。任意 「開封済み」
created_at TIMESTAMPTZ 登録日時。自動 NOW()
updated_at TIMESTAMPTZ 更新日時。自動 NOW()

DDL

CREATE TABLE ingredients (
  id           UUID         PRIMARY KEY DEFAULT gen_random_uuid(),
  name         TEXT         NOT NULL,
  quantity     TEXT,
  expiry_date  DATE,
  category     TEXT         DEFAULT 'other',
  note         TEXT,
  created_at   TIMESTAMPTZ  DEFAULT NOW(),
  updated_at   TIMESTAMPTZ  DEFAULT NOW()
);

-- 消費期限でのソートが多いので index を貼る
CREATE INDEX idx_ingredients_expiry ON ingredients (expiry_date ASC NULLS LAST);

-- updated_at の自動更新 trigger
CREATE OR REPLACE FUNCTION update_updated_at()
  RETURNS TRIGGER AS $$
  BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
  END;
  $$ language 'plpgsql';

CREATE TRIGGER set_updated_at
  BEFORE UPDATE ON ingredients
  FOR EACH ROW EXECUTE PROCEDURE update_updated_at();

フロントエンド型定義（TypeScript）

export type Category = 'meat' | 'dairy' | 'vegetable' | 'seasoning' | 'other';

export interface Ingredient {
  id:          string;
  name:        string;
  quantity:    string | null;
  expiry_date: string | null;  // ISO 8601 'YYYY-MM-DD'
  category:    Category;
  note:        string | null;
  created_at:  string;
  updated_at:  string;
}

// 音声認識→Claude解析の出力型
export interface ParsedIngredient {
  name:        string;
  quantity:    string | null;
  expiry_date: string | null;  // 'YYYY-MM-DD' or null
  category:    Category;
}

07. Claude API 連携仕様

① 音声テキスト → 構造化データ（/api/parse-voice）

使用モデル: claude-haiku-20241022（速度・コスト重視）

System Prompt — parse-voice
あなたは冷蔵庫の食材管理アシスタントです。 ユーザーが読み上げた音声テキストから、食材情報を抽出してJSONを返してください。 出力は必ず以下のJSON配列形式のみで返すこと。説明文は不要。 [ { "name": "食材名（必須）", "quantity": "数量と単位（不明なら null）", "expiry_date": "消費期限 YYYY-MM-DD形式（不明なら null）", "category": "meat|dairy|vegetable|seasoning|other のいずれか" } ] ルール: - 期限が「9月20日」などの場合、現在年（${currentYear}年）として補完する - 「明日」「来週」などの相対日付は今日（${today}）を基準に変換する - 数量が不明でも name が取れれば登録する - 複数食材が混在している場合はすべて抽出する

API Route 実装（route.ts）

import Anthropic from '@anthropic-ai/sdk';

export async function POST(req: Request) {
  const { text } = await req.json();
  const client = new Anthropic();

  const today = new Date().toISOString().split('T')[0];
  const currentYear = new Date().getFullYear();

  const message = await client.messages.create({
    model: 'claude-haiku-20241022',
    max_tokens: 1024,
    system: buildSystemPrompt(today, currentYear),
    messages: [{ role: 'user', content: text }],
  });

  const content = message.content[0];
  if (content.type !== 'text') throw new Error('Unexpected response');

  const parsed = JSON.parse(content.text);
  return Response.json({ ingredients: parsed });
}

② 献立提案（/api/suggest-menu）

使用モデル: claude-sonnet-4-5（品質重視）

System Prompt — suggest-menu
あなたは家庭料理の献立アドバイザーです。 冷蔵庫の食材リストを受け取り、実用的なレシピを3〜5品提案してください。 モード: ${mode} ${mode === 'quick' ? '- 期限切れに近い食材を優先的に使うレシピを提案してください' : ''} ${mode === 'request' ? `- ユーザーリクエスト: ${request}` : ''} 出力は以下のJSON配列形式のみで返すこと: [ { "title": "料理名", "time_minutes": 調理時間（分・整数）, "ingredients_used": ["使用する食材名", ...], // 冷蔵庫リストにある食材のみ "steps": ["手順1", "手順2", ...], // 3〜5ステップで簡潔に "memo": "一言コメント（任意）" } ]

リクエスト Body

{
  "mode": "quick" | "request",
  "request": "煮物が食べたい",  // mode === 'request' のときのみ
  "ingredients": [
    { "name": "鶏もも肉", "quantity": "2枚", "expiry_date": "2026-09-16" },
    { "name": "大根", "quantity": "半分", "expiry_date": "2026-09-18" }
  ]
}
コスト最適化のポイント
音声解析は Haiku（安価・高速）、献立提案のみ Sonnet を使う。 送信する食材リストは期限切れ含む全件ではなく、期限が近い順に上位15件に絞るとトークン節約になる。

08. UI・UXガイドライン

一覧画面の表示ロジック

  • 残り日数 = expiry_date - today。0日が「今日まで」、負数が「期限切れ」。
  • グループ順: 期限切れ（赤）→ 今日（オレンジ）→ 明日（黄）→ 今週（通常）→ それ以降（淡色）→ 期限不明（最下部）
  • 各グループ内はさらに expiry_date ASC で並ぶ
  • expiry_date が NULL の食材は「期限不明」グループに入れ、登録日の古い順に表示する
  • スワイプ左で「削除」ボタン、スワイプ右で「使い切り（削除）」ショートカット

音声登録のUX

  • マイクボタンは画面の中央寄り・大きく（最低56px）。タップしやすいこと
  • 録音中はボタンが赤くなり、パルスアニメーションで状態を示す
  • 文字起こし中はリアルタイムでテキストが流れる（確定文字と認識中文字を区別するスタイルで）
  • 「もう一度登録」ボタンで連続入力できる。冷蔵庫に複数食材を入れながら繰り返せる
  • 解析失敗時はトースト通知＋テキストを手動入力に切り替えるフォールバック

モバイルファースト原則

  • タップターゲットは最低44px × 44px（Apple HIG準拠）
  • ボトムナビゲーションはセーフエリア対応（pb-safe）
  • フォントサイズは最低14px。期限の残り日数は大きく表示して一目でわかるように
  • 読み込みはスケルトンUIで。スピナーは使わない
  • オフライン時は一覧表示のみ（キャッシュ可能な範囲で）、登録・AI機能はオフライン非対応で明示する
